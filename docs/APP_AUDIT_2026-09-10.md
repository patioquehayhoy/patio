## Correcciones implementadas

| Flujo | Problema corregido |
| --- | --- |
| Acceso | Los enlaces podían reutilizar la URL del arranque anterior, intercambiar dos veces el mismo código o entrar con una sesión distinta después de fallar el enlace. Se priorizan credenciales actuales, se comparte el intercambio en curso, se ofrece recuperación y no se registran tokens/URLs de acceso. |
| Inicio | Un Foodie autenticado creaba un negocio durante el arranque. Ahora la hidratación de negocio corresponde al rol Fondero. Un fallo de fuente ya no deja el splash bloqueado. La renovación de sesión sigue el estado activo de la app. |
| Identidad | Dos stores conservaban IDs de negocio distintos. Se unificaron y se agregó limpieza del estado de negocio. |
| Cuentas | Los datos locales de una cuenta permanecían visibles para la siguiente. Se archivan por cuenta, se restauran al volver y las escrituras se coordinan con las transiciones. Cerrar sesión conserva el trabajo local sin sincronizar en el archivo de su propietario. Los favoritos, listas y notas de invitado se incorporan al volver a una cuenta archivada; otros borradores de invitado se recuperan al salir. |
| Eliminación | Se agregó la acción en ambas cuentas, con confirmación y solicitud autenticada para la identidad confirmada. El servidor limpia Storage y usa un trigger transaccional para el negocio/datos relacionados. Requiere migraciones y ensayo real. |
| Publicación | Ya no confirma publicación sin negocio o sin platillos, ni anuncia cuando falla el guardado remoto. Los errores de borrado/guardado llegan al flujo que debe informar y conservar los cambios. |
| Día comercial | Menús, consultas y anuncios usan la fecha de Ciudad de México; UTC adelantaba el día desde las 18:00. Las reseñas también usan esa fecha. |
| Biblioteca | Se coordinan las modificaciones concurrentes para evitar perder favoritos, nombres o elementos. La publicación de colecciones pasa por un RPC transaccional con identidad estable para reintentos. |
| Borradores e historial | Se revisan identidad del borrador, publicación real e indicadores de hoy. La existencia de un borrador no demuestra que el menú se haya publicado. |
| Foto de menú | Errores de lectura/picker permiten reintentar; cancelar o salir evita que una respuesta tardía reactive la extracción. Los menús con JSON mixto o malformado se normalizan antes de dibujarse. |
| Descubrimiento | Búsqueda por frases, nombres y acentos, refresco al volver y protección contra respuestas tardías al cambiar de Patio. Abrir una ruta tiene alternativa web cuando la aplicación de mapas no está disponible. |
| Perfiles | Guardados de negocio, privacidad y perfil verifican la respuesta del servidor antes de confirmar. La foto de perfil se convierte a JPEG; errores de subida no guardan una URI privada del teléfono como avatar público. |
| Comunidad | Seguir perfiles y guardar colecciones tienen estados de carga/error/inexistente y conservan el destino al pedir acceso. Se agregaron reportes, bloqueos y desbloqueo en Privacidad, con reglas por usuario. |
| Notificaciones | Canal Android creado antes de pedir permiso; envío en lotes de 100; registro de fallos por dispositivo; comprobación de propietario y menú real antes del anuncio. Se difiere la navegación de una notificación hasta completar el arranque. |
| Seguridad IA | Las funciones validan al usuario, tipos, tamaño de petición y timeout; los errores no devuelven detalles internos del proveedor. Falta cuota persistente del servidor. |
| Enlaces externos | Se rechazan URLs nativas malformadas, excesivas o con codificación anidada antes de que llegue al decodificador antiguo de navegación. Es una mitigación; no elimina el aviso de dependencia. |
| iOS / Android | Icono opaco correcto, permisos mínimos, entornos de compilación explícitos, control de Maps/Firebase para Android y versión real en Cuenta. |
| QA | El runner Maestro ya no ignora errores ni sobrescribe todos los reportes. El smoke predeterminado evita flujos históricos que publican o crean datos. Se añadieron scripts de control y CI. |

## Validación

Los tests de aplicación usan implementaciones reales de TypeScript con dobles de almacenamiento, red y APIs nativas. Los tests de esquema incluidos en `npm test` inspeccionan contratos. Además, se ejecutó por separado un ensayo SQL real sobre PostgreSQL 18.3/PGlite 0.5.8 con un fixture mínimo: **14/14 comprobaciones aprobadas** de RLS, identidad, transacciones y cascadas. No sustituye una restauración del esquema real de Supabase ni prueba Auth HTTP, Storage o el gateway. [Ensayo SQL reproducible](../scripts/db-tests/README.md).

- `npm run check`: TypeScript, ESLint, regresiones y configuración estructural de lanzamiento.
- `npm run check:release:strict`: falla si faltan requisitos externos comprobables; no demuestra firma ni backend operativo.
- `npx expo export --platform ios --platform android`: compilación de los bundles JavaScript de ambas plataformas; no es un AAB ni un archive firmado.
- Prebuild nativo aislado de iOS/Android: verifica plugins, permisos, assets y SDK sin modificar el proyecto remoto.
- Compilación local Release para simulador iOS: **BUILD SUCCEEDED**, sin firma, con Xcode y `ios/` local existente. Smoke público cerrado 1/1 el 12-sep sobre ese binario; ver límites arriba. El prebuild aislado acredita la configuración nueva; este binario no acredita un archive de distribución.

## Dependencias

Se actualizaron dependencias dentro de los rangos declarados y se aplicó un override acotado de PostCSS 8.5.28, compatible con el worker de Expo. Se conserva Expo SDK 54 y el parche existente de react-native-maps.

La auditoría inicial reportó 41 paquetes afectados (16 altos, 25 moderados).
El corte del 10-sep bajó a 31. La consulta del 12-sep reporta **16 paquetes
afectados: 8 altos y 8 moderados**, originados en `image-size` y
`decode-uri-component`. Los avisos se propagan por la cadena de dependencias,
por lo que el número de paquetes no equivale al número de fallos independientes.

- `image-size`: versión usada por Metro; avisos por imágenes malformadas, sin versión corregida publicada durante la consulta. Revisar assets confiables y actualización de upstream. No se forzó un salto incompatible del SDK.
- `decode-uri-component`: cambiar a la versión ESM corregida rompe el consumidor CommonJS actual. Se añadió validación de entrada nativa como mitigación y se conserva el pendiente de actualización compatible.
- `uuid`: resuelto con overrides exactos de 11.1.1 para xcode y ngrok, usando el
  [backport oficial](https://github.com/uuidjs/uuid/releases/tag/v11.1.1).
  Las pruebas ejecutan los consumidores instalados: generación de IDs y
  escritura/lectura de un proyecto Xcode mínimo; nombres de túnel de ngrok con
  proceso/red simulados; rechazo de buffers insuficientes en v3/v5/v6. Se conserva
  el parche de react-native-maps y Expo SDK 54.

El paso de seguridad en `.github/workflows/quality.yml` permanece bloqueante si existen avisos altos. Un resultado verde de los tests no sustituye ese resultado. El workflow usa las acciones oficiales [checkout](https://github.com/actions/checkout) y [setup-node](https://github.com/actions/setup-node), generación v6, y Node 22 para ejecutar el proyecto. El workflow se añadió localmente; no se ejecutó en GitHub durante este corte.
